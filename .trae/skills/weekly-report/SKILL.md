# AI Tech Report

本文件定义采集、撰写与复核流程及详细写作规范；项目边界、内容红线、必备结构和发布权限以 `AGENTS.md` 为准。开始前读取该文件和 `sources.yml`；模板仅提供骨架与格式示例。

## 确定范围

- 运行 `python3 scripts/build.py --current-week`，取得符合 `AGENTS.md` 收集周期的周编号、起止日期与收集截止时间；用户明确指定历史周时据该周确定窗口。
- 依窗口执行完整扫描，不只补上次运行后的信息。
- 若本周报告已存在，读取其“速览”和“其他动态”（旧稿称“简讯”）及必要正文，重新核实后更新同一文件，不因去重丢失仍相关的已收录事件。
- 跨周去重先读上期“速览”，疑似旧闻延续再读对应正文，记录本期相对上期的实质新增点。

## 发现与筛选

多 Agent 协同模式可用时，优先并行执行信源扫描、开放检索和候选核实；由主 Agent 统一完成候选去重、选题、撰写与最终复核。

### 固定信源

- 逐项访问 `sources.yml` 的全部入口，并在底稿中记录每个入口的实际覆盖范围、检查结果，以及对应的候选编号或覆盖缺口。
- 访问失败最多重试一次；仍失败则记录缺口，不能标记为“已检查无新增”。

### 开放检索

- 首先在模型、应用与 Agent、基础设施、产业与政策四个方向，用不限厂商和站点的中英文关键词广泛发现，兼顾国内外科技媒体、垂直媒体和热点动态。
- 初筛后检查候选分布；存在遗漏的子领域、地区或主体，或结果过度集中、重复旧闻时，再进行针对性补查。
- 每个方向至少执行一组独立检索。可使用日期过滤或在检索词中写明起止日期，不依赖“本周”“最近”“最新”等相对时间词。

### 候选筛选

列表、榜单和搜索摘要只作发现入口。初筛确认标题、时间和核心变化；列表未覆盖完整窗口时补查日期范围或分页，仍有缺口则如实记录。不要把页面或模型文件的更新时间直接当作事件发布日期。

按 [底稿模板](assets/research-template.md) 创建 `research/YYYY-Www.md`，记录每个固定入口、每组检索、候选取舍及核心事实证据。

- 同一事件合并为一个候选；分别记录来源发布时间、事件发生时间和本期新增点，不凭文章日期推断事件日期，再按 `AGENTS.md` 的窗口与去重要求筛选。
- 按证据强度、变化幅度、影响范围与关注度线索筛选；热度和转载量不能代替影响力。按价值决定重点事件和“其他动态”的数量。
- 固定入口已尝试、开放检索完成且已补查已知缺口、候选去重且足以支持成稿时停止扩展搜索。

## 核实与撰写

- 入选事件逐条访问直接支持事实的官方发布、论文、项目仓库或可靠报道，在底稿中记录“核心事实 → 本次访问的链接”及数字的适用条件和来源性质。
- 融资金额、性能优势、事故归因、争议性指控等关键陈述应寻找独立佐证；多篇转载同一消息不算独立验证。无法核实的关键断言应删除，必要时放弃事件。来源访问失败最多重试一次，再换可靠来源或放弃。
- 按 `AGENTS.md` 的文件约定，以 [报告模板](assets/report-template.md) 起稿。周报标题概括重要变化或有依据的核心判断；正文不展示统计周期。
- 编号引用的语法见模板；文末来源按正文首次引用顺序编号，同一来源复用编号。
- 判断应建立在已核实的事实之上，不因叙事需要补充因果或动机；来源归属与措辞遵循 `AGENTS.md` 的内容红线。
- 围绕事件的关键变化及其影响选择事实、数据和分析；每段应提供新增信息或推进理解，篇幅与事件的重要性和证据丰富程度相称。比较应建立在可比的口径上。
- 根据素材组织正文，不为填满模板而补充内容。整体判断的范围与力度应与素材相称，直接叙述，不使用“本周”“这一周”“同一周”等周次引导语。事件分析用于解释具体影响。观点和事实分开，单个事件的判断使用对应正文后的引用块。
- 每个重点事件使用与“速览”并列的二级标题，不另加主题分组标题；标题写清主体、动作与关键变化，避免仅用产品、机构或议题名。“速览”每条以加粗的事件标题开头，与重点事件标题按顺序一一对应；标题后的叙述补充影响或限制，避免重复标题。
- 无需展开的新增动态归入“其他动态”，统一使用无序列表，每条采用“加粗标题＋中文冒号＋叙述＋引用”，不使用独立段落展开。每条叙述不超过 150 字（含标点，不计标题、Markdown 标记及引用链接）。
- 面向读者陈述具体事实和判断，不写解释写作过程的套话。

## 复核与交付

- 构建前重读入选来源，对照底稿逐条复核 `AGENTS.md` 的内容红线，并核对编号引用与来源条目一一对应、跳转有效。
- 将周报标题、事件标题、速览、整体判断和“其他动态”中的陈述与详细正文及直接来源核对，检查压缩后是否丢失关键限定。发现遗漏时在相应位置补回或改写，不能只在正文末尾集中说明。
- 同周重跑可以复用尚未清理的底稿作线索，但引用必须在本次重新访问；底稿已清理时从本期报告恢复已收录事件。
- 运行 `python3 scripts/build.py`，确认 `site/weekly/<周编号>/index.html` 存在。完成事实复核与构建后删除本次底稿。
- 扫描缺口在交付时说明，不在正文末尾附通用“覆盖说明”。向用户报告周报路径、收集窗口、核心内容和验证结果。
- 如需提交或发布，按 `AGENTS.md` 的“Git 与发布”执行。
